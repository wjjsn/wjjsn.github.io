## Turn 1

### 👤 User

怎么通过 cmd 挂载 smb 为磁盘？

### 🤖 Assistant

在 Windows 中，你可以通过 CMD（命令提示符）使用 `net use` 命令或 `PowerShell` 命令来将 SMB 共享文件夹挂载（映射）为一个本地驱动器盘符。
以下是具体的几种方法：

### 方法一：使用 `net use` 命令（最常用）
打开 CMD，输入以下命令并回车：

```dos
net use Z: \\服务器IP\共享文件夹名称 /user:用户名 密码 /persistent:yes

```
**参数说明：**

- `Z:`：你想分配给这个共享文件夹的**本地盘符**（可以换成其他未被占用的字母，如 `X:`、`Y:`）。
- `\\服务器IP\共享文件夹名称`：SMB 服务器的路径。
- `/user:用户名`：访问该 SMB 服务的用户名。
- `密码`：该用户名的对应密码。
- `/persistent:yes`：**持久化挂载**。这意味着重启电脑后，系统会自动尝试重新连接该磁盘。如果不想重启后保留，可以改为 `no`。

### 方法二：无需密码或使用当前凭据
如果你的 SMB 服务器允许匿名访问，或者你已经登录了具有权限的域账号，可以省略用户名和密码：

```dos
net use Z: \\服务器IP\共享文件夹名称 /persistent:yes

```
如果你想在回车后再手动输入密码（防止密码以明文形式显示在屏幕上），可以使用 `*` 代替密码：

```dos
net use Z: \\服务器IP\共享文件夹名称 /user:用户名 *

```

### 实用管理命令
挂载成功后，你可能还需要进行查看或删除，可以使用以下命令：

```dos
net use

```

### 💡 常见问题排查

1. **错误 53（找不到网络路径）：** 检查服务器 IP 是否正确，以及局域网内是否能 ping 通该 IP。
2. **错误 86（密码错误）：** 检查用户名和密码是否正确。如果使用的是微软账号，用户名通常是注册邮箱。
3. **提示盘符已被占用：** 请换一个未使用的字母（例如 `M:` 或 `S:`）。

### 👤 User

错误 5

### 🤖 Assistant

在 Windows 中，通过 CMD 挂载 SMB 磁盘时遇到 **“发生系统错误 5。拒绝访问。” (System error 5 has occurred. Access is denied.)**，这通常意味着**权限不足**。
请按照以下几种最常见的原因和解决方法进行排查：

### 1. 密码或用户名错误（最常见）
虽然提示是“拒绝访问”，但很多时候是因为输入的用户名或密码在 SMB 服务器端校验失败。Windows 可能会因为之前缓存了错误的凭据而直接拒绝。
**解决方法：**
在命令中明确显式地提供用户名和密码。如果用户名是本地账户或网络账户，可以尝试加上域名或计算机名（如果没有域名，用 `.` 代替）：

```dos
net use Z: \\服务器IP\共享文件夹 /user:.\你的用户名 你的密码

```
提示： 如果密码包含特殊字符（如 @, #, $ 等），请务必用英文双引号把密码包起来，例如 "P@ssw0rd!"。
### 2. 需要以管理员身份运行 CMD
如果当前用户没有修改网络映射的权限，可能会被拒绝。
**解决方法：**

1. 点击 Windows 开始菜单。
2. 输入 `cmd`。
3. 右键点击“命令提示符”，选择 **“以管理员身份运行”**。
4. 再次尝试你的 `net use` 命令。

### 3. 已存在冲突的凭据（连接冲突）
Windows 不允许同一个用户使用两个不同的凭据同时连接到同一个服务器。如果你之前已经连接过该服务器，或者 Windows 自动尝试用你当前的电脑账号去登录，就会冲突导致错误 5。
**解决方法：**
先清除现有的连接和缓存，再重新挂载：

```dos
net use * /delete /y

```

### 4. 服务器端的共享或 NTFS 权限不足
“拒绝访问”也可能是服务器端真实存在的限制。
**解决方法：**
确保在 SMB 服务器（如另一台 Windows 电脑、NAS 或 Linux 机器）上：

- **共享权限**：已赋予该用户“读取”或“更改”权限。
- **安全（NTFS）权限**：在文件夹属性的“安全”标签页中，该用户拥有相应的访问权限。

### 🤖 Assistant

这确实是一个非常关键的线索！
既然 Windows 能访问，但 iPhone 和 PE（通常是简化版的 Windows 或基于 Linux 的工具）无法访问特定路径，而其他路径一切正常，那问题确实不在于网络或密码，而在于 **Linux 服务端（通常是 Samba 配置文件 smb.conf）针对该特定路径的配置**，或者该路径在 **Linux 系统底层的权限设置**。
在 Linux Samba 服务的配置中，有几个最容易导致这种“选择性拒绝”的隐藏坑：

### 1. 路径中包含中文或特殊字符（编码问题）
iPhone (iOS) 和 PE 系统对网络路径的字符编码（如 UTF-8）要求比较严格。如果出问题的路径名称包含**中文、空格或特殊字符**，可能会导致它们解析失败，而 Windows 的兼容性较强，能自动识别。

- **排查方法**：去 Linux 服务器上，将该共享文件夹的名称和 Linux 路径都改成纯英文（例如 `Share` 或 `Data`），然后再用 iPhone 尝试。

### 2. Linux 底层文件系统的权限不足（最常见）
在 Samba 中，访问一个文件夹需要过**两关**：第一关是 Samba 的共享权限，第二关是 Linux 底层的 NTFS/Ext4 目录权限。Windows 有时候会缓存高权限凭据，而 iPhone 访问时可能被 Linux 识别为其他用户（比如 `nobody` 或 `www-data`）。

```bash
ls -ld /你的共享路径/出问题的文件夹

```

### 3. Samba 配置文件（`smb.conf`）中的参数差异
请打开 Linux 上的 `/etc/samba/smb.conf` 文件，对比 **“能访问的路径”** 和 **“不能访问的路径”** 的配置块。出问题的路径可能漏掉了一些关键参数。
请检查出问题路径的配置块中是否有以下漏掉或写错的参数：

```ini, toml
[出问题的共享名称]
   path = /你的共享路径
   browseable = yes
   writable = yes
   available = yes
   public = yes          # 是否允许公开访问（对比正常路径）
   guest ok = yes        # 如果不需要密码，确保这个是 yes
   valid users = 你的用户名 # 确保包含了你登录的账号

```

### 4. 软链接（Symbolic Links）限制
如果这个出问题的路径在 Linux 里是一个**软链接（快捷方式）**，指向了别的地方，Samba 默认为了安全会**禁止**客户端顺着软链接访问到共享目录之外，这会导致 Windows 以外的设备报错。

```ini, toml
follow symlinks = yes
wide links = yes
unix extensions = no

```
